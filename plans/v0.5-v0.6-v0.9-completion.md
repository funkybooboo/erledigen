## Design decisions

1. **NL dates: a small shared parser, NOT chrono-node.** The client
   bundle is size-gated (584 KiB) and the roadmap's phrase list is
   tiny; `packages/shared` already owns pure date-key math (dateKeys).
   New `parseDatePhrase.ts`: ordered array of small anchored regexes
   (the documented Bun backtracking trap) supporting today / tomorrow /
   yesterday, `in N days|weeks`, `next <weekday>`, bare `<weekday>`,
   `<month> <day>` (march 15, mar 15), and literal `YYYY-MM-DD`.
   Two entry points: `resolveDatePhrase(phrase, today)` (whole string
   must be a phrase -- reschedule input, `/go`) and
   `extractDatePhrase(text, today)` (scan free text, strip the match --
   task creation).
2. **NL task creation extracts BOTH dates and `#tags`.** The roadmap
   parenthetical says "tags are parsed; dates are not", but the shipped
   `createFromText` parses neither -- `#work` stays in the text. As
   built, both get extracted: `buy milk tomorrow #work #p1` becomes
   text "buy milk", date tomorrow, tags [work, p1]. Recurrence phrases
   still win first (a habit's schedule beats a date phrase).
3. **`r` and `m` open the same inline reschedule editor** (the roadmap
   describes two day/date pickers, but a task's day IS its date here).
   One row-level editor, two registry ids so the help table matches
   the roadmap; `t` opens an inline tag editor. All live in TaskRow,
   driven by a `uiStore` row-editor field (same pattern as
   `editingTaskId`), so Esc layering stays in one place.
4. **Redo extends the existing undo history.** Undo entries gain a
   `redo` counterpart; undoing pushes it to a redo stack, a new
   undoable action clears it. The matcher grows `Shift` support for
   modifier chords (`{mod}+Shift+Z`), keyed `shift+z`. Today only
   delete is undoable, so redo re-deletes the restored task.
5. **Priority sort + date range live in `ActiveFilters`** (persisted in
   `UserPreferences` like the tag filter): `sortMode: 'manual' |
   'priority'` and `dateRange: { from, to } | null`. The Filter modal
   gains a Sort section and a date-range section. Range filter windows
   the day list (days outside [from, to] stop rendering); Someday tasks
   carry no date, so the panel is exempt -- noted as an as-built delta.
6. **Mobile = CSS-only responsive pass.** Breakpoints in app.css /
   component styles: modals become bottom sheets (Modal.svelte media
   query), the Someday panel becomes a fixed overlay sheet, day-list
   padding shrinks. No JS mode switch -- one DOM, media queries.
7. **Holidays are a first-class entity AND part of the JSON backup.**
   `Holiday { id, name, date, createdAt }` with the full vertical:
   repository interface + in-memory + SQLite + contract suite +
   migration 006 + CRUD routes + OpenAPI schemas + WS events + API/Bruno
   tests. `ExportSnapshot` gains an OPTIONAL `holidays?` field (allowed
   without a version bump per ADR-008); JSON restore restores them when
   present. `.ics` import reuses the RFC 5545 parsing already written
   for `IcalImportAdapter` (extracted into a shared `parseIcal.ts`
   used by both) -- events become named-date holidays; POST accepts
   raw `.ics` text (file upload) or a URL the server fetches.
8. **Summary sections read existing data.** Overdue: incomplete tasks
   with `date < today` (days-late from `daysBetween`); streaks: per-habit
   stats already expose `currentStreak`; holidays: the new holiday
   store filtered to the next 14 days.
9. **Kanban drag is native HTML5 DnD, no dependency** (the bundle gate,
   and svelte-dnd-action was deliberately removed in the simplification).
   Columns map to `task.state` ('ready' | 'scheduled' | 'done'); the
   board shows tasks carrying the project's tag. Auto-distribution is a
   server-side `ProjectService` computation (spread the project's
   unscheduled tasks evenly across startDate..dueDate) exposed as a
   preview-then-apply endpoint; dependency indicators render a lock on
   cards whose `dependsOn` predecessor is incomplete.
